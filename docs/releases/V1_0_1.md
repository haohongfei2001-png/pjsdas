# PJSDAS v1.0.1

PJSDAS v1.0.1 is a patch release focused on correctness, failure-state truth, cloud/session lifecycle safety, and the authenticated AI access boundary. It contains the post-v1.0.0 fixes already validated on `main`; it does not introduce a new product surface or a gateway compatibility version bump.

## State and persistence correctness

- Quick Capture previews are bound to the exact parsed source text, so edits invalidate stale ChangeSets instead of allowing outdated proposals to be applied.
- Manual Process Event notification time refreshes when appropriate while preserving explicit user edits.
- Cloud sync clears stale success outcomes before a new operation, preventing an old success state from coexisting with a current failure.
- Decision Rules save/reset failures are surfaced and unsaved drafts are preserved instead of presenting false success.
- Fixed Event Guard keeps unresolved recruiting events unresolved when completion persistence fails.
- Discovery Profile save/error feedback is invalidated after visible draft edits, so only persisted values are represented as saved.
- Closing Local Backup cancels an armed restore intent and requires explicit file selection again before destructive restore.

## Cloud and session lifecycle

- MCP proposal review waits for initial cloud-session restoration, avoiding false rejection of valid Drive-backed proposals during startup.
- PJSDAS sign-out is blocked while sync, conflict resolution, account linking, or startup restoration is in flight.

## OAuth and MCP authorization boundary

- One-time AI Google-link callback state terminates after both success and failure, preventing stale OAuth callback replay.
- OAuth consent, Settings copy, protected-resource metadata, and regressions now describe the bounded MCP capabilities consistently.
- Autonomous Monitor/Gmail ingestion is reserved for Supabase-validated OAuth client sessions. Ordinary first-party PJSDAS sessions remain read/propose-only, while validated OAuth clients retain the existing bounded trusted-ingestion capability.

## Compatibility and release integrity

- Public product version: `v1.0.1`.
- Engineering milestone remains `v1.10`.
- Authenticated MCP gateway runtime remains `1.9.0-alpha.1`; no transport or tool-surface compatibility bump is required by this patch.
- The normal fail-closed production chain remains mandatory: CI and Browser E2E, exact production backend commit/capability verification, GitHub Pages deployment, post-deploy Production Self-Test, then version-pinned release publication.
