# Complete durable prepared intent — local, default off

This candidate extends the frozen complete-V5 staged document path. It is **not a production migration, activation, quota, retention policy, or broad command-family authorization**.

## Supported mechanism

`PJSDAS_WORKSPACE_ROWS_DURABLE_INTENT=1` requires the existing staged-document, row-read and row-write flags. Only the existing first-party abandon/original Undo and consent-v3 opportunity/original Undo families participate. Other families keep their original routes and capability stops. The durable capability requires the existing `public-v1` transport; it does not expose a new schema.

Before any staged-document upload, the server serializes the complete original prepared input and server-read preimage, including original timestamps, full V5 receipt context, complete compensation and unknown fields. The exact serialization is losslessly gzip-compressed and admitted atomically to the existing database. Its manifest binds the separately prepared effect chain. The RPC must still fit the existing 2 MiB transport capability, and decoded bytes must fit the prior fixture-owner reservation. No runtime function mints a reservation. A valid but incompressible bundle remains an explicit unsupported capability, **not a product size quota**.

The admission key is `(user_id, command_id)`, not an epoch-derived stage ID. The first atomic admission owns the original time, preimage, payload, authority and absolute deadline. Concurrent losers use that original bundle. An ambiguous admission response is resolved by reading the same identity, not by replacing it.

A fresh actual API request or scoped-factory invocation checks original immutable ledger replay first, then looks up the prepared intent **before any business reducer or Undo compensation evaluation**. It reauthorizes the current original principal/family and original grant ID/revision/client/version before the database releases prepared bytes. Regranting does not substitute a new grant. The decoded input is checked against independently persisted binding/deadline/digest fields. The original manifest must match before upload; durable recovery cannot fall back to a generic small-request writer. The pure transport delta/manifest serialization is repeated and hash-checked, but business core, models and jobs are not rerun.

## Integrity and budget

The decoder enforces canonical base64, compressed and raw hashes, exact decoded byte count, reservation-bounded decompression, a single canonical gzip member, and canonical JSON bytes. It rejects trailing data, concatenated gzip, alternate gzip headers, invalid UTF-8, duplicate JSON keys and invalid roots. Unknown compatible fields are retained rather than filtered.

The unchanged original 10-second staged commit budget includes preparation/compression/admission, transfer and recovery. Its absolute deadline is persisted and never reset by a new request, fragment or process. Public mutating wrappers check current original authority and the deadline both before and after the original operation **inside the same transaction**, so crossing the deadline while waiting for locks or finalizing rolls back that transaction. Expiry does not assert that a previously dispatched transaction rolled back: original authorized ledger replay remains the committed-outcome resolver, including after the deadline and after later revisions.

Runtime credentials cannot update/delete admitted rows. Fault-injection tests use the fixture administrator; integrity checks detect altered content against independent admitted bindings, not an omnipotent attacker who can consistently rewrite all trusted database records and business state.

## Explicit remaining gates

- Admission requires the **entire** compressed prepared bundle to fit one existing bounded RPC. Compression is not arbitrary large-command support or a resource-policy proof.
- Old flag-off partial stages never had complete durable prepared bytes. Enabling this flag cannot reconstruct missing bytes or silently replace that draft; the original counterexample remains retained.
- Global capacity, cumulative document/effect/spool accounting, retention, reclamation and crash cleanup policy are not established. No production retention interval or new quota is invented here.
- Large history/audit/individual-entity/header read limits, unrelated command-family capabilities, two genuinely staged-compatible hosted rollback releases and approved atomic migration transport remain separate gates.
- Native loopback timings and cold-process tests are not production RTT or remote 10-second feasibility evidence. The original absolute deadline deliberately refuses a recovery that no longer fits; it is not extended to force a pass.
- No production SQL, ACL, credentials, resource, provider, budget, publication, CI, merge or deployment change is authorized by this local work.

## Separately reproduced multi-workspace preimage-plan defect

The expanded restart matrix exposed a pre-existing finalizer query problem not covered by earlier single-workspace success. In an isolated 24-workspace fixture, statistics collected with only one workspace underestimated a new owner's 2,101 preimages and 2,102 effects as one row each. The original custom plan selected a nested loop whose item index condition used only the workspace; entity join predicates remained join filters. It reached the unchanged 10-second statement timeout. The generic plan for the same stale-statistics dataset was fast: generic-plan selection was **not** established as the cause.

A proposed `LATERAL ... LIMIT 1` rewrite was rejected after EXPLAIN showed the planner selecting the ordinal index with `id` left as a filter; it remained slow and also timed out in a no-statistics case. The accepted equivalent relation first materializes only the original stage's effects and the locked workspace's preimages, extracting effect key scalars once. It retains every original shape/preimage validation and subsequent set-based DML. The isolated custom/generic, absent/fresh/stale-statistics matrix verified exactly equal preimage output without changing work memory, statement deadline, production statistics or indexes. These are local diagnostic timings, not a production performance guarantee.

A later frozen-candidate replay exposed a second hotspot in the same finalizer: the original `DELETE ... USING large_effect` timed out after the preimage query had completed. The retained first candidate is therefore not the final passing artifact. The deletion statement now materializes only the original stage's explicit JSON-null deletion keys before joining the locked workspace's items. It stays **after all original preimage/shape checks**; it does not change authority, lock order, scope, UPSERT, manifest validation, receipt construction or transaction boundaries.

The expanded isolated diagnostic covers real abandon/archive and both Undo directions, plus a real archive/Undo with 300 interleaved retained actions, unknown entity fields, cross-collection equal IDs and equal keys across owners. It exercises absent, fresh and stale statistics under both custom and generic plans, and records the major table-backed shared-finalizer statements and representative relation shapes: preimages, delete, UPSERT, effect/duplicate reads, head/stage locks, the v3 actions projection, whole `valid_state` timing, head/stage updates, candidate original/Undo ledger reads, ledger insertion and audit size. It does not enumerate every nested function plan, every collection/history distribution, retained-ledger branch or pure-JSON authorization/Undo loop; simplified single-row write parameters do not stand in for full V5 receipt construction or per-effect SHA-chain costs. Exact complete preimages, target rows, updated revisions, unchanged foreign-owner full-row digests, manifests and deferred constraints are checked. The original v3 projection remained under the local statement deadline, so it was not rewritten; its original authorization/Undo guards remain unchanged.

These per-statement EXPLAIN measurements are diagnostic only. They neither replace the actual API/scoped-factory end-to-end 10-second gate nor establish production capacity. In particular, some misestimated plans still perform quadratic scalar comparisons; removing repeated JSONB extraction is not a proof of linear scaling. The original statistics, failed plans and rejected rewrites remain evidence rather than being hidden by forced runtime plans or a larger budget.

A separate small mixed archive/Undo equivalence gate compares the original private apply helper and staged helper. It covers valid complete state, missing/malformed after rows, absent/stale preimages, ordinal gaps/collisions and duplicate effect identities, with complete rollback checks. Duplicate identities retain the existing earlier staged append unique-index rejection (`23505`, entire page rolled back), versus the original array helper's `22023`; this is documented, not falsely called identical error timing. No product route to either private helper is added.
