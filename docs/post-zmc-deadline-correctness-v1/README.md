## Time display contract

Legacy timezone values describe normalization/provenance. Their exact instants are displayed in the user/browser display timezone. Only a valid source-explicit timezone selects a source clock; if it differs from the display timezone, the label includes its actual GMT offset, including DST. Today, Schedule, and job-detail operation/node/action labels use the same display policy. A date-only or floating date remains the original calendar date, with no fabricated hour. No stored instant, timezone, provenance, or record is rewritten.

## Feasible work selection

The consumer planner now chooses a feasible subset instead of appending tasks already judged impossible. Ordinary deadline selection uses earliest-deadline dynamic programming over whole estimated task costs; explicit start constraints use the bounded search described below. Every selected prefix fits its own physical deadline after reserving fixed commitments and configured work windows, including windows after local midnight. Known user capacity imposes an additional stricter limit; unknown capacity stays unknown and only actual physical time is used.

The objective maximizes the sum of squared existing priority scores, with a 2,500-point bonus for an action already `doing`. Existing priority includes opportunity value, fit, urgency, stage, leverage, delay cost and cost efficiency; prep graph enrichment remains part of that ranking. This prioritizes valuable work and work already underway without inventing a completion percentage or a dependency from a name. Ties use stable action identities. The selection is derived from current facts and remaining time, so reload/restart at the same time produces the same subset; passing a feasibility boundary can legitimately change it.

Unselected hard work is a distinct read-model result, retained outside today's executable task rows. One contextual notice names the selected work and every unselected item, gives a direct job link, and recommends skipping a same-day deadline or adjusting a later commitment. This is a recommendation; it does not abandon an opportunity or modify an action. Schedule and job history retain all records.

## Review and verification boundary

The first independent review found two valid P2 cases: a next-day work window was omitted before a cross-midnight deadline, and a source clock needed a timezone label. Both were repaired and added to the permanent unit/browser regression. The subsequent fresh review caught a daily-capacity boundary when today’s window is shorter than the combined cross-midnight horizon. Capacity is now constrained per calendar day, including next-day date overrides; unit cases cover 10 minutes today plus 50 tomorrow, and the browser case requires the combined horizon to exceed today’s window cap. The next review reproduced two further allocation boundaries: an explicit Today allowance incorrectly capped tomorrow, and tomorrow’s hard-work minutes consumed today’s flexible budget. The allowance is now daily, and deadline-prefix reservation calculates only the hard work that must occur today. Both have permanent regressions. A further review checked an explicit latest-start boundary: not-yet-started work now also respects its separate start and completion obligations, while work already underway has satisfied that start requirement. The regression prevents flexible work from consuming all time before the stated latest start. Work can continue after a gap until the actual deadline; that instant is never shortened. Selection checks separate deadline-demand profiles when explicit starts exist, with exhaustive subset checks for both constraints. Review reproduced an exponential frontier on 18 explicit-start tasks; that frontier was replaced with suffix-knapsack upper bounds and deterministic branch-and-bound. Ordinary deadline selection remains exact polynomial dynamic programming. Explicit-start search is exact when its upper bound closes or search completes (including all six-task regressions); unusually complex larger cases retain the best verified feasible subset at a deterministic comparison budget rather than freezing Today. Tie regressions preserve identity ordering for equal-utility subsets. Search improves utility before spending the remaining budget on ties, preventing a 28-action equality family from hiding a higher-value two-task subset. This limit and whether search completed are internal read-model diagnostics, not a user banner. Cross-browser gates also reproduced WebKit losing the original job/Today opener because mouse clicks need not focus a button; navigation now records the actual activated element, preserving the original focus assertions and new deferred-item return path.
