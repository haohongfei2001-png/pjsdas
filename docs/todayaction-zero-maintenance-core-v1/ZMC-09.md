## Permanent dense browser journey

`e2e/zmc09OwnerDenseAcceptance.e2e.ts` runs two connected browser contexts against one synthetic authoritative workspace. It starts with 384 actions, 358 retained historical Gmail decisions, 300 schedule nodes, and a six-hour daily capacity. The first Today screen has fewer than 20 tasks, real upcoming nodes, no historical decision CTA, no parser decision, and no maintenance status. A background Gmail audit write moves the server from revision 1004 to 1005 and reaches actual IndexedDB through passive refresh. The first device then records an offline command. A second device commits a different action. The first browser process closes and relaunches with its persistent IndexedDB profile and account outbox, then reconnects. It sends exactly one business command with the original command ID and base revision, retires the outbox, retains both actions, the Gmail audit record, all 358 decisions, and all 300 nodes. A newly added current web decision with two actual opportunity choices appears as exactly one business question. The historical Gmail records stay out of Today.

Local boundary after the browser additions: 208 unit files / 1,096 tests, TypeScript/production build, and full headless Chromium Browser 158/158 passed. The real browser-process restart and Schedule cancellation cases also passed 2/2 in headless WebKit. Local Firefox could not start its temporary profile (`Could not find profile folder`) before the test ran; the remote Firefox/WebKit Matrix is the required verification for that engine. Remote exact-head gates and independent review remain.
