# 业务 v7 受控测试：实施与已批准执行范围

2026-10-04，项目所有者已在会话中明确批准下述两个合成身份、原插件客户端、业务 v7 及初始化的受控测试，最长 24 小时；本文件记录该具体范围，不构成其他授权。仅使用现有资源；不新增付费方案、不开放公众、不新建插件、不改变现有用户的受众角色或权限。运行时新增消费级范围只有业务 v7（独立准备事项、手动行动、申请分组）。v3 机会、v4 规划、v5 发现偏好、v6 私人提醒另行明确同意。

## 已落实的代码边界

- 服务端 `PJSDAS_CONSUMER_TEST_ACCOUNT_IDS` 必须恰好包含两个不同的有效 UUID；`PJSDAS_CONSUMER_TEST_CLIENT_ID` 必须是核验后的原插件 OAuth client UUID。缺失、通配符、重复或多于两个账号一律拒绝。值不放入客户端、Git 或插件包。
- 新业务工具需要同时满足：消费级开关开启、事务写入模式、allowlist 中的有效 beta、精确 A/B 账号、精确原 client、正确 MCP token resource。读取/写入/撤销仍逐次核验本人对应 client 的有效 v7 授权及版本；名单不是业务授权。
- 受控身份的 MCP 目录和调度器只提供三个业务 v7 工具，不继承原有 25 个通用工具；猜测旧工具名同样拒绝。服务端测试标记独立于开关和名单保存，关闭或移除配置不会退回旧目录。首次同意前及撤权后，业务读取只返回授权说明，不读工作区。其他现有未标记账号保持原目录。
- 已有 owner v2 及独立的 owner v3–v6 路径保留；这次不启用任何 owner 管理开关。其他现有 beta/owner 不会因为消费级开关开启获得 v7。
- 普通测试用户只能新增业务 v7。伪造规划授权或混合批次由服务端拒绝，不能部分批准。底层受信任的 SQL 函数仍兼容历史多领域能力，不能将 service_role 的调用能力等同于普通用户权限。
- 空工作区初始化也限定 A/B 有效 beta，并需要独立 onboarding 开关、第一方登录、明确空白开始。已有工作区返回原数据；不覆盖、不重新导入、不重置时区。
- `https://todayaction.com/?scoped_access=1` 是第一方撤权入口。关闭全部消费级/owner 开关、移出名单/受众或断开 OAuth 后，仍可用本人第一方会话查看本人领域授权元数据并撤权。页面隐藏初始化和新增授权；服务端拒绝新增授权。撤权不依赖 OAuth provider 列表可用。
- 撤权仍要求允许的站点来源、本人会话、expectedAccountId、当前授权 id/revision、明确选择与确认。委托 token、跨账号和陈旧证明不能撤权。只开放撤权不会暴露工作区内容。
- 开关关闭后，新请求不注册消费级工具；已经进入事务的写入可能先完成。数据库撤权锁测试区分“写入先提交”和“撤权先提交”，不承诺取消已提交修改。撤权后的陈旧读写/撤销及旧授权重放均拒绝。

## A/B 隔离方案与验收证据

A/B 由开发侧安排，是两个独立合成测试身份，不能用同一账号的两个会话冒充双账号。执行方负责创建、登录、账号切换、领域同意、全部验收和清理；用户不提供两个邮箱，不操作测试。各自真实 Supabase `auth.users.id` 必须不同；绝不复用个人主账号或含真实资料的工作区。现有隔离测试已具备 A/B/C；本轮两个新身份、精确 beta 准入和消费级开关已获上述限时授权；实施前仍须完成清理能力检查。

| 身份 | 准入和数据 | 验证结果要求 |
| --- | --- | --- |
| A | 精确 A UUID + beta + 原 client；仅合成 A 标记 | 明确批准 v7 后读写撤销；撤权后拒绝 |
| B | 精确 B UUID + beta + 同一原 client；仅合成 B 标记 | 仅自己的数据/回执；不能用 A 对象、grant 或 command 证明；A 操作不改变 B |
| C | 仅在合成数据库中建立的现有用户对照样本 | 不在 A/B 名单；不开新工具/初始化/授权；旧权限和数据逐行保持 |

真实验收使用隔离宿主会话和独立浏览器存储。先分别记录 A/B 工作区 revision、内容摘要、授权 id/revision 和命令回执，再运行：A 写入、相同命令重试、读取、撤销；A/B 同名命令及外来对象/证明；请求未结束切换账号；关闭/返回、Back/Forward、登录中断恢复；A 撤权与写入竞争。对每一步比较 B 的工作区、授权、回执无变化，随后反向验证 B 操作不影响 A。截图只含合成内容。

其他真实用户不参与测试，不借其 token、不写入其工作区、不向其发布新授权。C 的拒绝和旧 v2 回归使用隔离测试库，避免给第三个真实账号新增权限。线上只读结构/计数检查不能替代隔离数据证明，也不能声称实时业务中全部用户的数据摘要绝对不变。

自动验证分层：`consumerControlledAdmission.test.ts` 覆盖准确名单/client 与领域拒绝；`consumer-migration-chain.mjs` 在 PGlite 和 CI 独立 PostgreSQL 数据库中逐项验证八项 SQL、旧行保持、v2 重放/写入/撤销、A/B 证明互借和跨账号撤销拒绝以及 B/C 无变化；`consumer-business-flow.mjs` 通过真实第一方 handler、执行器和 PostgreSQL 完成 v7 初始化→授权→读写/撤销→全部关闭→撤权→拒绝。原并发、原始字段、回执家族碰撞测试保留。桌面/手机三浏览器检查关闭后的撤权界面。所有这些均为合成验证；真实插件安装验收须另行执行。
