# Product Intent

## Product responsibility

PJSDAS is a personal job-search operating assistant. It should maintain a trustworthy model of the
user's recruiting reality and continuously turn that reality into the few things the user needs to
know or do.

It owns routine maintenance work: receive facts from trusted sources; resolve the correct
opportunity/process/occurrence; preserve source identity/history; auto-commit safe compensatable
internal facts when authorized; protect temporal commitments; surface executable next work; ask only
for real human decisions; and recover truthfully from offline, ambiguity, delay or failure.

The user should not have to operate PJSDAS as a second job.

## Daily promise

The product makes four things obvious:

- what to do now;
- what cannot be missed soon;
- what PJSDAS already handled;
- what genuinely requires the user's decision.

Today is the high-frequency action surface. Opportunities are persistent recruiting contexts.
Tell PJSDAS is a context-aware natural-language expression surface. Automation stays in the
background and exposes outcomes/exceptions, not transport internals.

## Complexity hidden from normal use

Normal UX must not require snapshots, revisions, CAS, ledgers, source reconciliation, Supabase
versus IndexedDB authority, Gmail cursors/leases, deployment topology or capability flags.

Translate them into consequences: saved, pending, outcome being confirmed, source stale, two sources
disagree, Undo unavailable because a dependent update exists.

## Truthfulness

Transport health is not semantic completeness. Input accepted is not authoritative save.
Contract/capability flag is not live capability. Elapsed time is not completion. A context page is
not the underlying external action. Normal unsupported boundaries are not generic unresolved
business failures.

## Owner / AI boundary

AI/engineering own ordinary architecture, component structure, libraries, visual hierarchy,
spacing, accessibility, testing, compatibility, performance, refactors and bug fixes.

Owner decision is required only for materially different product-value tradeoffs, irreversible
data/permission changes, new material cost, privacy/legal boundaries, protected external
consequences, or genuinely non-dominated product directions.

The owner is not the pixel designer, implementation selector or substitute QA team.

## Non-goals

No category reset, database rewrite for cleanliness, native iPhone work, UU-08, new external
application authority, unapproved permission expansion or automatic release publication.
