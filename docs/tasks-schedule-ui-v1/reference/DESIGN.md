# PJSDAS · 任务与日程 / 第二版产品设计

状态：独立交互设计，不是生产实现。不修改 GitHub、数据库或真实账户。
此版本取代上一版 R4.1 的界面提案，而不是给上一版再加一层皮肤。

## 1. 产品结构先改变

三个平级目的地：**今天 / 岗位库 / 日程**。

- 今天：今天可执行的全部任务 + 未来节点的连续时间流。没有“最佳任务”hero，没有“首项 / 备选”的二等分层。
- 岗位库：所有公司和岗位的稳定归档，投递前、推进中和已结束的岗位都能找到。不是另一份今日清单。
- 日程：求职事项的完整时间线，包括过去实际发生的行动、过去待确认的安排、今后的固定安排/可参加窗口/截止时间。不是工程审计日志。

今天右侧与日程读取同一套日程数据。右侧只取未完成的未来节点；日程保留历史与全部未解决事项。未来不是一张独立维护的列表，也不通过粘贴假数据填满。

“岗位库”比“投递库”更合适：可以容纳尚未投递、面试中及已结束的岗位，不会暗示只有已投递记录。

## 2. Today 的新主次

页标题只是“今天”与日期。下面两个完整面板，任务约占 58%，节点约占 42%；两侧标题对齐。

任务：公司 → 岗位 → 真实时间约束 → 动作。每一项使用相同的字体、结构和操作级别。紧急程度只影响时间的语义色，不使一项任务吞掉页面。

取消：推荐宣言、常显理由、预计用时、时间预算切换、重复岗位详情按钮、覆盖提示、最近处理模块、常态同步耗时、快捷键标签。保留：真实缺失信息/待保存/冲突等影响当前操作的信号。

任务本身与节点不同：今天可以“准备下周的面试”；面试时间仍放在右侧的下周，而不伪装成今天发生。完成准备也不完成面试。

任务完整列出；已完成可在底部展开，不占据待办首屏。点公司/岗位进入该岗位详情，动作按钮只做其标注的动作。打开外部申请入口不自动视为已投递。

## 3. 连续节点，不再只显示三条

桌面右栏拥有独立滚动区，列头常驻。滚动到底继续加载后续实际数据，没有“只显示最近三个”的上限；到真正末尾明确显示“已显示全部节点”，不制造无限假记录。列表可通过键盘滚动，焦点不会因补充内容跳到头部。

设计原型按批次延迟呈现已有合成数据；这只验证浏览行为，不声称已实现服务器分页。在生产中使用既有日程读取模型，必要时采用稳定排序键的 cursor 分页；追加数据不能改动排名、时间精度或身份。

已过时间但无结果：在右栏头部用一条“X项过去安排待确认”入口呈现，点开日程的对应过滤结果；不抢占未来首屏，不默认成功/失败。

窄屏：Today 内用“任务 / 节点”切换显示同一对区域，默认任务；一次点击就能看节点，不必先滑过整份任务。全局仍只有三个目的地。200%文字时也进入此结构，不把字号缩回去。

## 4. 日程与岗位详情

日程默认按时间排列“全部”；可切换“接下来 / 已发生”，并可回到今天。历史行动用明确的已完成标记；过去待确认安排使用“待确认”；未来用面试、测评、投递截止等事件类型。日期精度不升级，只有日期的节点显示“具体时间待定”，不补23:59。

岗位详情承载完整职位名、当前进展、下一步、申请截止/面试窗口、为什么今天安排、可选准备材料、相关历史及来源。低频信息只出现于详情，不复制到每个列表行。

日程项点击查看事件详情；岗位名称进入相应岗位。取消/改期保留原历史，不创建两个同时生效的日程。

## 5. 全局录入与异常

全局“告诉 PJSDAS”保留，移除可见快捷键。只有一个输入框与一个提交动作；识别结果显示具体目标及变化，再确认记录。不是聊天主页，也不展示技术模式列表。

- 常态：不显示绿色健康面板、延迟数或架构说明。
- 初次加载：同布局骨架，不闪空工作区。
- 空工作区：简单的首个录入入口，不给六个空模块。
- 离线/刷新失败：保留已有内容，用短状态和必要的恢复动作。
- 正在保存：受影响的动作不可重复提交；关掉弹窗后仍可恢复查看。
- 未知结果：先确认原操作状态，不重新生成一次提交。
- 真正冲突：详情内比较已保存值与拟改值，保留输入，不静默覆盖。
- DecisionRequest：作为需要“确认”的真实任务出现；不要再新增第四个导航。

账户、连接、显示与数据放在低频设置中。原型场景选择器只放在“设置 → 设计验证”，不作为正式产品功能，也不在Today底部常驻。

## 6. 视觉系统

中性冷白背景、白色面板、深蓝黑正文、克制的蓝色交互。不是原来的灰绿色。每列一个容器，不给每行再套一张卡；靠细分隔线与一致的对齐组织密度。

字阶（基准16px）：页标题26；区块标题17；公司16；职位14；时间与辅助信息13；按钮14。字号全部使用rem，允许200%放大。行高1.5–1.65。空间：4/8/12/16/24/32px；常规行高由内容决定，约88–100px；不靠固定高度裁掉长文字。

所有交互命中区域至少44px；焦点清楚可见；语义颜色附带文字；长岗位可换行并在详情中完整阅读。最多一层模态框，Escape关闭且恢复发起按钮焦点。减少动态效果，尊重reduced-motion。

## 7. 实现边界

这是可运行的界面提案：所有记录为合成示例，写入只发生在当前页面内存。演示录入/标记完成/改期/撤销用于验证界面的连贯性，不是后端正确性证据。无真实投递、邮件、费用、权限修改。

未来实施时保留 authoritative command、Supabase/Postgres authority、CAS、receipt、Undo、source identity、authorization，以及时间/流程/准备语义。允许删除原有UI分层和低价值控件，但不在视觉重构中私自删除用户记录。
